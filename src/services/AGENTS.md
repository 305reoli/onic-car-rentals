# Services rules
- Phase B downloads complete private checkout documents with size limits/base64/SHA256; only whitelisted reply metadata persists in booking_audit. Known-success retries omit files; preview sends require admin + is_test, because receiver idempotency owns document/agreement/email creation.

- Global Pays webhooks go through `src/services/gpWebhook.server.ts` (secret check, bare-route orderId lookup, provider consult before settle); checkout BRL quotes show only provider `calculateQuote` data via `gpPayView.ts`, never a client-side conversion.
- Card payments use Lovable built-in payments via `src/services/stripe.server.ts`: sandbox fallback, live only with a non-empty managed live gateway connection; raw Stripe keys are rejected because gateway identifiers are not Dashboard keys. Embedded checkout requires a matching public token; banners use server mode. Signed `/api/public/payments/webhook?env=sandbox|live` uses separate secrets and disables live without a live connection; event idempotency and forward-only status remain. Booking totals use `dueAtBooking`/`paymentMode`; legacy partial settings are ignored. Every new Stripe booking uses automatic capture for every category. Manual-capture support remains only for already-created historical sessions; it must never be selected for a new booking. Only explicitly accepted substitute price differences can use the former balance columns; no rental balance endpoint or deadline exists. Global Pays real API runs only when `settings.globalpays_live` is ON (`loadGpSwitch`), otherwise simulator.
- Paid Stripe checkouts become bookings only via `finalizePaidBooking` in `src/services/finalize.server.ts` (webhook primary; client submit, in-page confirm, booking page and admin Recover reuse it); the draft-only status-guarded update is the single lock for owner/customer emails, and paid payments without a booking go to `payment_orphans` + owner alert, so a closed tab never loses a paid booking.
- Fleet sync v2 (SistemaGestao contract): vehicle triggers queue rule (six fields) and availability events in `fleet_sync_outbox`; inbound v2 goes only through `apply_sistemagestao_fleet_v2` (event-id hash idempotency, stale revisions ignored, inbound flag = no echo); SistemaGestao blocks live in `fleet_sync_remote_availability` and are enforced via `remoteBlocks` in carIsFree/search; compare + divergence check live in `fleet-check.server.ts` and never auto-correct.
- Fleet outbox is drained every minute by the managed `fleet-sync-flush` schedule (`/api/public/jobs/fleet-flush`) plus the admin-save flush; outgoing v2 `vehicle.updated` fills unchanged blanks with effective values via `wireRulesEnvelope` (SistemaGestao requires all six), skips blank-only changes, and HTTP 400 is terminal (`rejected`). Outbound fetches use `redirect: "manual"` because workerd rejects `"error"`. Vehicle deletes queue via a DEFERRED constraint trigger (commit-time, row verified gone) and the sender re-checks `lifecycleStillValid` before any delete/archive, so a failed delete never archives SistemaGestao; v2 rule events carry photos; daily_price is frozen both ways (trigger, `wireRulesEnvelope`/`stripPrice`, `rulesPatch`, `apply_sistemagestao_fleet_v2`; only initial vehicle.created carries it); SistemaGestao permanent 409 reasons (`TERMINAL_409`) are terminal because it replays the first response per event_id.
- Documents step: licence country "Brazil" keeps uploads; any other country uses Stripe Identity via `identity.functions.ts` (managed gateway only, private `client_ref` proof, outputs fetched server-side into `identity_verifications` and copied to `prereservations.identity_verification` on attach). Rules live in `src/lib/identity.ts`; SistemaGestao gets `identity_verification` only for verified clients and no loose main-driver licence files. Card payment completion auto-calls submit (finalize lock keeps it idempotent). Verified sessions email the owner once via `identity-notify.server.ts` (webhook + attach path; atomic `identity_verifications.owner_notified_at` claim); rejected (requires_input + non-"abandoned" last_error) or canceled sessions email once via separate `owner_failure_notified_at`. Progression is non-blocking: a submitted identity (processing/verified, latched per session) passes the Documents gate; attach stores PENDING/FAILED stripe identity via `loadAttachableIdentity` and webhooks resolve it. Failed sessions also email the renter once (`client_failure_notified_at`) with a fresh booking-tied session. Report reads fall back to the non-sensitive report because the gateway key cannot expand number/dob/expiry.
- Client insurance: optional `insurancePolicy` slot (PDF allowed only there) maps to SistemaGestao `insurance_policy`; choice/status live on prereservations insurance_* columns, owner review + denial email via `insurance.server.ts`; `InsuranceUpload.tsx` is the MeasureOne integration point so checkout flow never changes.
- US-license insurance: no Sua-coverage option and no MeasureOne button/dialog/iframe in checkout (MeasureOne blocks framing); with settings.measureone_static_link set, attach records insurance_us_flow=measureone_pending_after_payment (server-side) and the link is delivered only after payment via MeasureOneCard and one email (`measureone-email.server.ts`, atomic measureone_email_sent_at claim; `measureOneAfterPayment` fires at payment time from finalizePaidBooking and the Global Pays request settle, plus customerMessage on approval — the claim keeps it to one send); the checkout done screen also renders MeasureOneCard; MeasureOne bookings get the owner status control without a file; insurance minimums class reads body_category first (legacy tier only refines SUV/sedan to luxury); empty link → direct declarations upload. measureone_started is legacy only.
- Inbound v2 availability updates naming a site_vehicle_id that differs from the stored fleet_sync_links pairing are refused with 409 pairing_mismatch (no writes, no auto re-pair); unmapped cars still learn the pairing, so mis-filing can never be silent.
